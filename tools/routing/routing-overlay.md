### Disambiguation rules (hand-curated, not stated in any agent's own description)

1. Spark imports (`pyspark.*`, `org.apache.spark.*`, `SparkSession`, DataFrame/Dataset ops) → route to the `spark-*` family, never the plain `scala-reviewer`/`python-reviewer`/`scala-implementer`/`python-implementer` pair, even though the file extension matches.
2. Within `spark-*`: checkpoint/watermark/`transformWithState`/streaming-source diffs → `spark-streaming-specialist` first; `spark-scala-reviewer`/`spark-pyspark-reviewer` for everything else in that language.
3. Rust reviewers stack, they don't replace each other: start from `rust-idiom-reviewer` on every diff, and additionally run `rust-performance-profiler` for perf regressions or `rust-api-designer` for public API/semver shape (its own description already routes `unsafe`/FFI to `rust-unsafe-ffi-auditor` and async/Tokio to `rust-async-concurrency-reviewer`). Two more sit outside the per-diff flow: `rust-toolchain-auditor` owns Cargo.toml/lockfile/workspace/CI-gate debt (route dependency or build-config changes there, not to the code reviewers), and `rust-test-strategist` owns whether tests actually prove the change (route "is this tested enough?" questions there).
4. Repo has a `.jj/` directory → `jj-workflow` owns commit/rebase/bookmark operations; don't shell out to raw `git` via Bash for those repos.
5. `architecture-reviewer` complements, not replaces, the language reviewer's line-level pass on a large diff: run architecture-reviewer first, then the language pair.
6. Reverse-engineering work runs in this order: `game-data-format-analyst` on the shipped data first (containers, tables, scripts, error-string schemas), `rea-binary-analyst` only for what the data cannot answer, `re-findings-auditor` before a package is handed over, then `re-findings-porter` to vendor it into the consumer repo. `physics-model-reconstructor` owns the simulation model and its reference oracle; `graphics-pipeline-reconstructor` owns render passes and encodings and routes engine work to `unreal-render-specialist`. Every constant that crosses from findings into code carries a provenance label (`re-provenance-guidelines`).
7. C++ reviewers stack like the Rust ones: `cpp-idiom-reviewer` on every diff, plus `cpp-memory-safety-auditor` for lifetimes, UB, and FFI boundaries, `cpp-concurrency-reviewer` for threads and atomics, `cpp-performance-profiler` for measured hot paths, `cpp-api-designer` for public headers and ABI shape. `cpp-build-auditor` owns CMake, presets, toolchains, and CI gates; `cpp-test-strategist` owns whether tests prove the change. The same stacking applies to `c-*` (with `c-abi-designer` for headers that mirror Rust `#[repr(C)]` types) and `lua-*` (with `lua-embedding-auditor` for the C API boundary and sandboxing).
8. Any file under an Unreal module (`Source/**`, `*.Build.cs`, `*.Target.cs`, `*.uproject`, `*.uplugin`, `Config/*.ini`, editor Python under the project) routes to the `unreal-*` family, not to the plain `cpp-*` pair, even though the extension matches. `unreal-reviewer` is the per-diff entry point; `unreal-physics-specialist`, `unreal-render-specialist`, and `unreal-editor-automation` take the deep topics. A Rust static library linked into Unreal splits at the C header: Rust side to `rust-unsafe-ffi-auditor`, header to `c-abi-designer`, Unreal side to `unreal-reviewer`.
9. Development platforms are macOS and Linux. Reject advice that assumes Visual Studio, MSVC-only flags, or Windows paths as the default in any family above.
